# Threat Model

Daftar threat per elemen DFD berdasarkan kategori STRIDE.

| ID | Elemen DFD | STRIDE | Aset | Threat statement |
|----|------------|--------|------|------------------|
| T-01 | DF-03 / P-03 | Denial of Service (D) | A-07 | Pengguna publik anonim dapat mengirimkan berkas PDF berukuran raksasa secara serentak terhadap aliran DF-03 dan proses P-03 melalui ketiadaan pembatasan ukuran payload di tingkat server/HTTP request (meskipun modul P-02 memiliki batas ukuran, buffer memori server Next.js sudah membengkak duluan saat membaca body request sebelum diteruskan ke P-02; batas 10 MB di verify-form.ts hanya ditegakkan di sisi klien), sehingga alokasi memori server habis (out-of-memory crash) dan layanan verifikasi lumpuh total bagi seluruh pengguna. |
| T-02 | P-04 / DF-08 | Spoofing (S) | A-09 | Penyerang eksternal dapat menyamar sebagai pengelola regulasi (E-02) terhadap modul autentikasi P-04 melalui serangan brute-force pada endpoint login akibat belum adanya pembatasan frekuensi percobaan masuk (rate limiting / account lockout) pada rancangan modul autentikasi, sehingga penyerang berhasil menebak kata sandi, mengambil alih sesi admin, dan leluasa memanipulasi katalog regulasi. |
| T-03 | D-04 / DF-16 | Repudiation (R) | A-05 | Administrator dengan hak akses basis data dapat menyangkal telah mengubah status atau memalsukan regulasi terhadap data store D-04 melalui celah rancangan di mana rekaman log audit hanya disimpan sebagai baris basis data biasa yang dapat dimodifikasi atau dihapus langsung tanpa proteksi integritas, sehingga audit forensik kehilangan bukti yang tak terbantahkan (non-repudiation) atas siapa pelaku perubahan sebenarnya. |
| T-04 | P-01 (Berjalan) / DF-03 (Rancangan) | Tampering (T) | A-06, A-07 | Pengguna teknis dapat mengirimkan data formulir atau berkas yang dimanipulasi langsung ke server terhadap DF-03 / P-03 melalui validasi yang saat ini hanya berjalan di sisi klien (fungsi asli: validateVerifyForm), sehingga payload tidak valid atau parameter di luar skema lolos ke logika sistem saat P-03 diimplementasikan di server nanti. Catatan: pola kelemahan validasi satu sisi sudah berjalan di P-01 sekarang, dampaknya baru nyata setelah endpoint server P-03 aktif menerima data. |
| T-05 | DF-17 / P-03 | Information Disclosure (I) | A-10 | Penyerang eksternal dapat memperoleh API Key AI (A-10) melalui kelalaian pengembang memberi prefiks NEXT_PUBLIC_ sehingga Next.js menyertakan kunci rahasia itu ke dalam bundel JavaScript sisi klien, padahal pemanggilan DF-17 semestinya dilakukan tertutup dari server (P-03), sehingga kuota AI eksternal dicuri dan disalahgunakan pihak luar. |
| T-06 | P-03 / DF-11 | Elevation of Privilege (E) | A-07, A-08 | Pengguna publik biasa (E-01) dapat memicu mutasi status atau mengubah metadata regulasi pada proses P-03 melalui ketiadaan verifikasi klaim sesi dan otorisasi peran admin (missing role check) pada Server Action pembaruan data, sehingga pengguna yang tidak berhak berhasil mengeksekusi operasi istimewa admin. |
| T-07 | A-12 (rantai dev) | Denial of Service (D) | A-12, A-01 | Paket pihak ketiga braces dapat menghentikan atau memicu crash proses pengujian, linting, dan build terhadap mesin dev / proses build melalui kerentanan stack exhaustion (advisory GHSA-vfj7-8cjw-p6xm) akibat pemrosesan pola ekspresi bersarang yang tidak dibatasi pada rantai dependensi braces, micromatch, fast-glob, @next/eslint-plugin-next, eslint-config-next (npm audit melaporkan 5 high; npm audit --omit=dev melaporkan 0 kerentanan), sehingga alur kerja pipeline CI/CD atau mesin pengembang terhenti akibat alokasi memori call stack meluap. |
| T-08 | D-05 / DF-10 | Information Disclosure (I) | A-09 | Penyerang yang menembus akses penyimpanan basis data dapat membaca seluruh rekaman hash dan salt kata sandi admin (D-05) karena data tersebut tersimpan telanjang di baris tabel yang dapat dibaca, di mana ketahanan dan kecepatan offline cracking sangat bergantung pada algoritma hash yang keputusannya masih dikoordinasikan dengan Kripto T2, sehingga kredensial admin berisiko direkonstruksi sepenuhnya. |
| T-09 | D-02, D-03 / DF-13, DF-14 | Tampering (T) | A-03, A-04 | Penyerang dengan hak akses tulis ke server penyimpanan dan basis data dapat mengganti berkas PDF regulasi beserta nilai sidik resminya secara bersamaan terhadap D-02 dan D-03 melalui ketiadaan perlindungan integritas terpisah pada rekaman sidik resmi di basis data, sehingga pengguna memverifikasi dokumen regulasi palsu dan sistem tetap menyatakannya sah karena kalkulasi SHA-256 berkas tetap cocok dengan sidik resmi yang ikut dimanipulasi. |
| T-10 | DF-18 / P-03 | Tampering (T) | A-11 | Pengguna publik berniat jahat (E-01) dapat merusak keabsahan interpretasi hukum terhadap respons AI (DF-18 / P-03) melalui penyisipan instruksi manipulatif (indirect prompt injection) ke dalam teks dokumen unggahan yang diekstrak lalu dikirim ke model AI via DF-17 (catatan: ekstraksi teks PDF ke AI ini masih berupa asumsi arsitektur dan belum tertulis eksplisit di PRD), sehingga model menghasilkan ringkasan kepatuhan yang keliru dan menyesatkan. |

Mayoritas elemen yang dianalisis berstatus Rancangan (lihat dfd.md); ancaman pada elemen Rancangan menggambarkan kelemahan yang akan muncul bila kontrol tidak dirancang. Yang berjalan sekarang: P-01 (T-04), rantai dependensi dev (T-07).
